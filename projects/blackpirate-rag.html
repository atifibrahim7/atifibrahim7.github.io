RETRIEVAL RETROFIT / VECTOR STORE AUGMENTATION PRODUCTION (CORE)

BlackPirate RAG

Better retrieval. Same store.

Retrofits advanced retrieval onto a vector store you already built, no rechunking, no re-embedding, no migration, even when the original chunk text is gone.

Rebuilding the corpus
is the tax nobody pays.

Upgrading retrieval quality usually means rebuilding the corpus underneath it: rechunk everything, re-embed everything, re-index, migrate, re-validate. For a production store, that is a project measured in weeks of engineering time and compute budget.

It is exactly the kind of migration that gets scoped, prioritized against everything else, and then never scheduled, which means the teams running the oldest, least-documented vector stores are the ones stuck the longest with the retrieval quality they started with.

A retrofit,
not a rebuild.

BlackPirate RAG connects to a vector store someone else already built, Qdrant, Weaviate, or pgvector, through a connector and a per-tenant field map. It reads what is there, classifies it, and writes its own fields back additively: it only ever adds its own keys, never touches or moves what was already in the store.

Production vector stores are often missing the original chunk text entirely, dropped after indexing to save space, or never stored in the first place. BlackPirate classifies every chunk into one of five cases, from full original text available down to embedding-vector-only, and for the degraded cases it reconstructs what it needs, estimated semantic density, likely pivot points, from the geometry of the embeddings themselves and from metadata priors, rather than from text that no longer exists.

Every inferred field carries a confidence tag: exact, validated, prior-based, geometry-derived, or null. That tag is a weight in downstream ranking, so a value the system had to guess never scores as if it had been read directly off real text.

The calibration step is the part worth dwelling on. Rather than trusting its own design assumptions, the system self-supervises: it takes chunks in the store that do still have real text, deliberately hides that text, runs its own inference path on them as if the text were gone, and compares the guess against the ground truth it is holding back.

What makes it
different.

Works on a vector store you already have: no rechunking, re-embedding, or migration.

Writes back additively only; nothing existing is modified or moved.

Handles the realistic case where original chunk text is gone, a five-case taxonomy from full text down to embedding-only.

Every inferred field carries a confidence tag that changes how much it is trusted downstream.

Self-supervised calibration: measures its own inference accuracy against real text it deliberately hid, and corrects its shipped defaults from that measurement.

Supports Qdrant, Weaviate, and pgvector as connector backends.

Measured, not
projected.

A first calibration run, 228 real samples, held-out test split, found the shipped confidence weight for one inferred signal was wrong in direction: measured correlation was negative where the design assumed strong positive. That weight was corrected from 0.45 to 0.20 before shipping.

For a second inferred parameter, the fitted value of 1.95 replaced the shipped default of 0.7, cutting held-out prediction error by 12.7%.

The calibration harness caught its own methodology bugs along the way: one candidate fitting approach was mathematically incapable of ever distinguishing a good setting from a bad one, and was replaced before it produced a single misleading result.

Earlier design documentation for this project cites larger projected ranking-quality improvements. Those figures come from a design-stage estimate with no independent benchmark behind them yet, so they are intentionally left out here in favor of the calibration results above, which are real, measured outcomes.

Built with.

Core retrofit, classification, and calibration are in production use. Two edge-case source types, drifted text and cold storage, are classified but routed through a fallback path rather than fully handled yet.
